# Data and interpretation

## ECMWF

Source: [ECMWF open-data specification](https://www.ecmwf.int/en/forecasts/datasets/open-data), downloaded using the official `ecmwf-opendata` Python client from ECMWF and its AWS mirror. Model: IFS deterministic/control, 0.25-degree GRIB2. Attribution: ECMWF, [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/).

- `swh` (140229): offshore significant height of combined wind waves and swell, metres internally.
- `pp1d` (140231): peak wave period, seconds. Mean period is not substituted.
- `mwd` (140230): mean wave direction, degrees from true north, meteorological FROM convention. This is not direction at the spectral peak.
- `10u` / `10v` (165 / 166): 10 m wind components, converted to knots and meteorological FROM bearings.

The current wave and atmosphere streams are `wave` and `oper` for 00/06/12/18 UTC cycles. Each supplies three-hour steps through 144 hours. The saved example is a real model forecast, not synthetic data. It is a reproducible snapshot, not a claim of current conditions when opened later.

## Fixed grid selection

The first valid significant wave height field was searched once for the smallest great-circle distance to the requested coordinate. Land/missing cells were excluded using the GRIB bitmap. The result, distance, flattened index, and grid signature are in `config/offshore_grid.json`. Subsequent calls load the saved record. A changed grid or missing forecast value raises an error instead of silently searching again. Wind is extracted at the same fixed offshore point and represents offshore model wind, not a beach observation.

## Transformation

`H_nearshore = coefficient * H_offshore`. This estimates nearshore significant wave height (Hs), not breaking-wave face height.

The lookup is taken exactly from the existing project's `surf_forecast.py` (`ROW_MAPPING`, `COL_MAPPING`, and `transfer_matrix_indices`):

- Rows: 15, 30, ..., 345, 360 degrees, where 360 represents north.
- Directions: round half-up to the nearest 15 degrees, with circular wrapping.
- Peak period: round half-up to integer seconds, then clamp to 4-24 seconds.
- Integer period to zero-based column: `24:0, 23:1, 22:1, 21:2, 20:2, 19:3, 18:3, 17:4, 16:4, 15:5, 14:6, 13:7, 12:7, 11:8, 10:9, 9:10, 8:11, 7:13, 6:15, 5:16, 4:17`.
- Columns 12 and 14 are unused in that legacy lookup. They are preserved, not reinterpreted as evenly spaced periods.
- Tide does not modify this fixed matrix. It is plotted independently.
- One metre is exactly `1 / 0.3048` feet. Plot wave heights are in feet.
- The weekend surf curve and AM/PM bands use the requested traditional/Hawaiian display convention: half the transformed nearshore height in feet (2 becomes 1, 6 becomes 3, 12 becomes 6). Conversion happens before AM/PM band selection. Raw model/CSV values and primary/secondary offshore swell heights remain physical feet/metres. This display convention does not turn modeled significant wave height into a measured breaking-wave face height.

## BOM tide test data

Source: [BOM 2026 station NSW_TP004 high/low tide table, page 4](https://www.bom.gov.au/ntc/IDO59001/IDO59001_2026_NSW_TP004.pdf).

Copyright Commonwealth of Australia 2025, Bureau of Meteorology. Station NSW_TP004 is a regional coastal proxy, not a prediction at the exact forecast coordinate. The published datum is Lowest Astronomical Tide (LAT). Times include daylight saving when in effect.

The 38 events in `data/bom_tide_events.csv` were transcribed from the published table for 28 September-7 October 2026 and checked against its date and time headings. The CSV preserves explicit UTC offsets, including the switch to UTC+11 on 4 October. They are real astronomical predictions, not observed water levels.

The smooth line is a half-cosine interpolation between successive high/low extrema. Only the marked events are BOM predictions; intermediate values are an approximation generated by this project. No values are extrapolated beyond the source table. The notebook raises an explicit coverage error outside this window.

Live runs now download the seven-day high/low prediction table from BOM's public `reg.bom.gov.au/australia/tides/scripts/getTidesTable.php` service for station `NSW_TP004`. Each request starts one day before the plotted weekend so events bracket both boundaries. BOM's explicit UTC timestamps are checked against its offset-aware local times, including daylight saving. Units, gaps, duplicates and coverage are validated before rendering; failed downloads never fall back silently to the test CSV. Downloaded events and retrieval/source metadata are saved under `output/bom_tides.csv` and `output/bom_tides.json` (not published).

These are astronomical predictions for the existing regional proxy station, not measured water levels or a surge forecast at the beach. The drawn curve remains local half-cosine interpolation; only high/low events are directly supplied by BOM. Offline preview runs use the saved test table, and `--tides` explicitly selects a saved table.

## GFS

The GFS option requests the GFS Wave 0.25° marine model from [Open-Meteo's Marine Weather API](https://open-meteo.com/en/docs/marine-weather-api), plus its standard forecast API for 10 m wind. The API documentation lists wave height, wave direction, wave peak period, swell and secondary-swell variables, and identifies GFS Wave 0.25° as a three-hourly global model. Open-Meteo attribution and licence terms apply. This is a separate GFS source path; ECMWF remains the EC option.

[BOM tide conditions, copyright and disclaimers](https://www.bom.gov.au/oceanography/projects/ntc/nsw_tide_tables.shtml) apply to the source predictions and modified products. This project is not endorsed by BOM. Before public deployment, include the required BOM disclaimer with the figure or through a clear attribution link as specified in those conditions.
